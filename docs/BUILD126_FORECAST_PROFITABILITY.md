# Build 126 - Forecast profitability from original sales reports

Adds a 74px Rating column immediately after Product. Its width is taken only from the existing 35% Product region; historical quantity, trend, confidence and final forecast retain their starting positions and widths (20%, 15%, 14%, 16%). A scoped responsive Settings button lives with the existing Forecast controls.

The rule matches the Reorder Generator v113 profitability calculation, but reads only the independent Forecast report history. First sum recorded profit VALUE in SAR per exact sales-source name across the current 12-month window. Then calculate the arithmetic mean of strictly positive product totals. Defaults: Super >= 3x mean; High >= 1.5x mean; Medium >= 0.5x mean; Low > 0 below Medium; Loss <= 0. This is not profit-margin percentage, monthly average profit, or a copied Master classification. Invalid/missing profit produces Review, never zero. Missing months are not estimated.

The benchmark and rating remain annual when a reporting month, search or rating filter is selected, preventing classification changes caused merely by filtering. The previously deferred profitability filter is enabled. Individual product info and the badge tooltip show actual annual profit and the benchmark. Supplier enrichment remains deferred; quantities, unit conversion, trend arithmetic, Annual Growth and Generate gates remain unchanged.

Settings supports Apply, Cancel and Reset defaults, previews monetary thresholds and enforces Super > High > Medium > 0 with maximum 1000. Preferences save in browser storage for the signed-in account under a Forecast-only key; they are not organization-wide settings, a database approval, or an update to ROP. Storage failure explicitly reports session-only persistence. Refresh and Clear filters retain applied settings; logout clears financial view state and closes the settings dialog.

Backend: add only profit fields to the existing source-mode v121 RPC. Preserve legacy nonempty-code behavior, active-user authorization, empty search_path and denial of anonymous access. No raw sales, Master, inventory, approval or ROP records are written; no parallel product database is added. The additive response is compatible with older clients.

Validation: exact inverse regression checks preserve Build125 and earlier baseline hashes. Model tests cover every threshold boundary, zero, negative, invalid, missing and absent positive benchmarks. Responsive browser checks verify the unchanged quantity-column position, all existing controls and sales quantities, settings validation/cancel/apply/reset/persistence, filtered ratings, source-only products, empty Master, failure/retry, zero/negative sales and eight desktop/mobile widths. Original uploaded monthly CSV profit totals independently reconcile to database aggregates. No private source records are committed.
